# 需求对齐单（迭代 2）：BoardPet 体验优化　日期 2026-10-10（对齐完成待终确认）

> 承接 v0.1（见 docs/需求对齐单.md）。本轮为存量系统的三项变更，已收敛，开放问题清零。

## 当前理解
在已交付的 BoardPet v0.1 上做三项改动：①**数据提速**——消除"打开面板等 1~3 秒、点开比赛详情等 3~6 秒"的等待，做到打开即有内容；②**修好走动**——宠物从右侧走到中间就停住的问题（含一个会让走动永久卡死的拖拽缺陷）；③**取消鼠标滚轮缩放**，保留设置面板的大小滑杆。

## 已实测的现状（根因）
| 现象 | 实测 | 根因 |
|---|---|---|
| 打开赛程面板慢 | scoreboard 请求 1.2~3.4 秒（gzip 后体积极小） | 赛程缓存 TTL 45 秒 == 轮询间隔 45 秒 → 打开面板时缓存几乎总是刚好过期，被迫空等一次完整网络请求 |
| 点开比赛详情慢 | summary 请求 2.8~6.1 秒（原始 435KB / gzip 42KB；瓶颈是 ESPN 首字节延迟 0.9~1.9 秒） | 球员数据只在点击时才请求，无预取；TTL 仅 20 秒；等待期间只显示"加载中" |
| 走到中间停住 | 代码为「走 5~12 秒 → 停 20~60 秒」 | 上轮为降 CPU 把休息调到 20~60 秒，从右侧走到屏幕中间恰好用完走动时长，随即进入长休息 |
| 走动可能被永久卡死 | 拖拽用 mousedown/mousemove/mouseup，无指针捕获 | 宠物窗口仅 200px，拖拽时鼠标一旦移出窗口就收不到 `mouseup` → 走动状态永久停在"拖拽中" |

## 已确认决策
| 编号 | 决策 | 理由/背景 |
|---|---|---|
| I1 | 取消鼠标滚轮缩放；设置面板的大小滑杆保留 | 用户第 2 轮选择；滚轮易误触发，"调整大小"能力不消失 |
| I2 | 修复走动：节奏改为「一直溜达、偶尔停 2~5 秒」，并一并修复拖拽丢失 mouseup 导致走动永久卡死的缺陷 | 用户第 2 轮选择 A |
| I3 | 数据提速采用「极速档」：①启动即预取赛程（并常驻缓存，由轮询器每 45 秒写穿刷新）②stale-while-revalidate——命中过期缓存先返回旧数据、后台静默刷新并广播更新（面板/详情永不空等）③自动预取进行中比赛与关注球队当日比赛的球员数据 ④面板中鼠标悬停某场比赛即预取该场球员数据（点击时通常已就绪）⑤赛程面板窗口在启动时预热（隐藏创建），打开即渲染 ⑥详情窗先用赛程缓存渲染比分头部，球员表随后就绪 | 用户第 2 轮选择 A |

## 范围外（明确不做）
- 不更换数据源（继续用 ESPN 免费公开接口），不做多数据源容灾
- 不做数据的本地磁盘持久化与历史比赛离线查询
- 不改比赛详情的展示字段与布局
- 不改动形象/配色/关注机制等 v0.1 已有功能

## 默认假设（未确认，按此执行，随时可改）
- 走动步速由 60px/s 提高到约 90px/s（观感更"活"）
- 预取节制：只预取「进行中」与「关注球队当日」的比赛数据，冷门历史场次按悬停预取，避免无谓请求
- 详情窗自动刷新保持 20 秒（仅进行中）；终场数据缓存 1 小时（沿用 v0.1）
- 内存预计增至约 370MB（原 318MB + 预热窗口约 50MB），沿用已知的内存豁免基线
- 启动时新增 1~2 秒后台网络请求（不阻塞 UI、不影响启动速度感知）
