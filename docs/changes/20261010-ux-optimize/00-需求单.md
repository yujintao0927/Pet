# 需求单：20261010-ux-optimize　日期 2026-10-10

## 结论
分类：**2 项行为变更 + 1 项缺陷修复**（其中「取消滚轮缩放」为行为变更，「走动停住」为缺陷修复并附带一个真缺陷，「数据提速」为体验优化）。三项均为用户直接反馈，详见 docs/需求对齐单-迭代2.md。

## 1. 背景与动机
BoardPet v0.1 已交付并日常使用，用户反馈三处体验问题：
1. 获取赛程与具体比赛信息太慢——打开面板等 1~3 秒、点开比赛详情等 3~6 秒。
2. 小人从屏幕右侧移动到中间后就停止移动。
3. 鼠标滚轮缩放容易误触发，要求取消。

## 2. 期望行为
| 现状 | 期望 |
|---|---|
| 打开赛程面板需等一次完整网络请求（实测 1.2~3.4 秒），期间只显示"加载中" | 打开即有内容（优先显示缓存），后台静默更新；进行中/关注/悬停过的比赛详情秒开 |
| 宠物走 5~12 秒后停 20~60 秒，观感像"走到中间卡住"；拖拽时鼠标移出窗口会永久丢失 mouseup，走动被永久暂停 | 一直沿底边溜达、偶尔停 2~5 秒；拖拽任意情况（含鼠标移出窗口）都能正常结束并恢复走动 |
| 滚轮在宠物上滚动会改变大小（易误触） | 滚轮不再改变大小；设置面板的大小滑杆保留 |

## 3. 验收标准
- [ ] 冷启动后首次打开赛程面板：出现内容的时间 ≤ 0.5 秒（有缓存时）
- [ ] 打开面板到显示最近一次数据的等待时间，从平均 1.2~3.4 秒降到 <0.5 秒（缓存命中即渲染，后台刷新后自动更新）
- [ ] 进行中比赛、关注球队当日比赛、面板内悬停过的比赛：点开详情 ≤ 1 秒显示比分与球员数据
- [ ] 未缓存过的历史场次详情：先用赛程缓存渲染比分头部（≤0.5 秒可见），球员数据就绪后补齐
- [ ] 宠物连续走动 ≥ 60 秒内累计行走时间占比 ≥ 80%，单次停留 ≤ 5 秒，不越出屏幕工作区
- [ ] 拖拽宠物（含把鼠标拖出宠物窗口外再松开）：走动在 ≤ 3 秒内自动恢复，不再卡死
- [ ] 在宠物上滚动鼠标滚轮：窗口大小不变
- [ ] 设置面板滑杆调整大小仍生效并持久化
- [ ] 断网时：面板显示"数据暂不可用 + 重试"，有缓存时优先显示缓存且宠物本体不受影响
- [ ] v0.1 既有功能全部回归通过（见 01-影响分析.md 回归清单）
