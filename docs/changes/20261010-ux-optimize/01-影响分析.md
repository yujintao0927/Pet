# 影响分析：20261010-ux-optimize　日期 2026-10-10

## 结论
影响面**中等**：改动落在 5 个主进程文件、4 个渲染层/preload 文件、1 个测试文件，均为内部实现调整。**无接口契约变更、无数据结构变更、无配置格式变更（settings.json v1 结构不动），不需要数据迁移。** 唯一高风险点是「轮询器必须改为强制刷新」——否则赛程缓存变长会导致关注事件（开赛/下半场/反超/赛果）漏报，此项列为首要回归项。

## 2. 受影响清单
- **直接影响**：宠物窗口交互（滚轮/拖拽/走动）；赛程面板与详情窗的数据获取路径（`dataService` 三个读取方：面板、详情窗、轮询器）。
- **间接影响**：
  - 关注事件检测（src/main/watchDetector.js 依赖 poller 传入的赛程快照新鲜度）——**必须回归**；
  - 通知与庆祝触发（src/main/notifier.js、petWindow.celebrate 调用链）——行为不应变化；
  - 内存占用（预热窗口 + 详情预取缓存）预期 +50MB 左右；
  - 打包产物（asar 内含新增文件 tests 不入包；预热窗口在打包态行为一致）。
- **不受影响**：形象与配色（src/shared/character.js、presets.js）、设置面板其余项、托盘、单实例锁、位置自愈逻辑、打包脚本。

## 3. 兼容性结论
- **接口**：无对外接口。IPC 通道只新增不修改（`data:prefetchSummary`），同一版本内 preload 与主进程一起发布，无旧客户端问题。
- **数据结构**：settings.json 结构不变，无需迁移；缓存结构仅在内存中变化（重启自然重建）。
- **存量行为**：滚轮缩放被移除属**有意的行为变更**（用户确认）；其余既有行为保持不变。
- **数据源**：不改（ESPN 免费公开接口），不新增外部依赖。

## 5. 风险与等级
| 风险 | 等级 | 应对 |
|---|---|---|
| 轮询器漏改强制刷新 → 关注事件漏报（用户会静默失去提醒） | **高** | R1 作为首要回归项；单测覆盖事件检测 + 代码检查 `poller` 调用的是 `refreshScoreboard` |
| SWR 后台刷新与 UI 渲染并发导致闪烁/重复渲染 | 中 | 现有 `render()` 幂等，广播沿用同一 `events:gameUpdate` 通道；冒烟验证面板在刷新后数据一致 |
| Pointer Events 在 Electron 中与拖拽窗口定位配合异常（屏幕坐标取值） | 中 | R7 实机验证拖拽位移一致；保留 `screenX/screenY` 取坐标 |
| 预热窗口使内存 +50MB | 中 | 已知豁免；实测记录在测试记录中 |
| 预取请求过多触发免费接口限流 | 低 | 仅预取进行中/关注球队比赛；悬停预取有去重（在途请求合并） |
