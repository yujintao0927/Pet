# 变更方案：20261010-ux-optimize　日期 2026-10-10

## 结论
采用单分支主干直改（与 v0.1 一致），分三个可独立回滚的提交实现：`feat: 数据提速`、`fix: 走动`、`feat: 取消滚轮缩放`。**无破坏性数据/接口变更**，回滚方式为 `git revert <commit>` + 恢复旧 release 产物（构建前会先备份）。

## 1. 实现思路

### 1.1 数据提速（C5~C12）
核心是把"请求后才显示"改成"先显示缓存、后台刷新"：
- **缓存分层**：每个缓存条目记 `at`（时间戳）、`data`、`inflight`（在途请求）。读取时：命中且在 `FRESH_MS` 内 → 直接返回；命中但已过期 → **立即返回旧数据**并触发后台刷新，刷新成功后通过事件通知 UI 覆盖渲染；未命中 → 同步等待请求（这种情况只发生在真正冷启动的首屏）。
  - 赛程 `FRESH_MS = 300_000`（5 分钟；由轮询器每 45 秒强制刷新写穿，实际总是新鲜）
  - 详情：进行中 `FRESH_MS = 15_000`；已结束 `FRESH_MS = 3_600_000`（终场数据不变）
- **强制刷新路径** `refreshScoreboard(date)`：轮询器专用，绕过缓存直连网络，并在获得新数据后广播；避免事件检测被缓存短路（对应影响分析中的高风险项）。
- **预取** `prefetchSummaries(ids)`：并发上限 3，在途请求去重，单个失败不影响其它（`Promise.allSettled`）。触发时机：①启动时对进行中+关注球队比赛 ②每轮轮询后同上 ③面板内鼠标悬停该场比赛（`mouseenter`，天然去重）。
- **感知优化**：详情窗打开时先读赛程缓存，用其中的比分/节次立即渲染头部，球员表就绪后补齐；赛程窗口启动时隐藏预热，点击即显示（显示时按宠物当前位置重定位）。

### 1.2 走动修复（C2~C4）
- 节奏：`startMoving` 设定走 15~35 秒，`walkTick` 到达后 `stopMoving(2500~5000)` → 一直溜达、偶尔停 2~5 秒；步长 `dir*2` → `dir*3`（约 91px/s）。
- 拖拽卡死：渲染层改 `pointerdown/pointermove/pointerup` + `root.setPointerCapture(pointerId)`，鼠标移出窗口仍能收到 up；`window.blur` 兜底解除拖拽态。
- 主进程看门狗：`movePet` 记录 `lastDragAt`；`walkTick`（250ms 周期）发现 `dragging && now-lastDragAt > 8000` 则强制解除，双保险。

### 1.3 取消滚轮缩放（C1）
仅删除 `wheel` 监听块；`pet:resize` IPC 与主进程 `resizePet` 保留（设置面板滑杆仍走 `settings:set → resizePet`）。

## 2. 接口/行为变更对比
| 项 | 变更前 | 变更后 |
|---|---|---|
| 滚轮悬停宠物 | 缩放 60%~250%，每次 ±5% | 无任何效果 |
| 走动节奏 | 走 5~12 秒 → 停 20~60 秒 | 走 15~35 秒 → 停 2.5~5 秒 |
| 走动步速 | 60px/s | ≈91px/s |
| 拖拽结束判定 | 依赖窗口内 `mouseup`（移出窗口会卡死） | 指针捕获，移出窗口也能正确结束 |
| 赛程面板首屏 | 等一次网络请求（1.2~3.4 秒） | 命中缓存立即渲染；未命中才等待 |
| 比赛详情首屏 | 等 summary 请求（2.8~6.1 秒） | 先用赛程缓存渲染比分头；球员表就绪即补齐（预取命中时≈0 等待） |
| IPC | — | 新增 `data:prefetchSummary`（增量，不破坏旧行为） |
| 内存 | ≈318MB | ≈370MB（预热窗口） |

## 3. 回滚方案
1. 代码：`git revert <数据提速 commit> / <走动 commit> / <滚轮 commit>`（三个提交互相独立，可单独回滚）；或 `git reset --hard <迭代前 tag>`。
2. 产物：构建前将现有 `release/BoardPet-win32-x64/` 备份为 `release/_backup_before_ux/`，回滚时直接换回并重建快捷方式（快捷方式指向同一路径，无需改动）。
3. 配置：本变更不改 settings.json 结构，无需回滚配置。
4. 验证回滚成功：启动应用 → 宠物出现、面板能打开、走动正常。

## 4. 测试要点
- 新增单测：SWR 语义（即时命中不触发请求／过期先回旧值且触发一次后台刷新／并发去重／预取失败不抛出）。
- 重点回归：R1（关注事件检测仍触发）、R7（拖拽与点击判定）、R5（滑杆调大小）、R8（走动不越界）。
- 冒烟脚本扩展：面板首屏耗时打印、详情窗两次打开耗时对比（冷/热）、滚轮无效断言、缩放后工作区断言。
