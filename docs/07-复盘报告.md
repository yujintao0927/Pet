| 范围 | PRD 18 项功能 + 4 里程碑 | 全部交付，1 项非功能指标豁免（内存），3 项受限待补验 | 内存目标 200MB 在 P1 写得太乐观；赛事触发验证受当日赛程（季前赛两场已结束）限制 |

## 踩坑记录
1. **NBA 官方接口（cdn.nba.com）在本网络被 Akamai 拒绝** → 调研阶段实测发现并当轮切换 ESPN 公开接口 → 教训：数据源可行性必须在 P0 用真实网络验证，不能假设文档说可用就可访问。
2. **透明无边框窗在 Windows 125% DPI 下反复 `setPosition` 尺寸持续漂移**（200px 窗口 10 秒涨到 615px）→ 用「带固定宽高的 `setBounds`」替代 → 教训：Electron 窗口 API 在非整数缩放屏幕上不可信赖单一维度调用，读-改-写要同时写回尺寸。
3. **ESPN boxscore 的 labels 与预期字段名不符**（实际 `FG/3PT/FT`）→ 改用 `keys` 机器名 → 教训：解析第三方数据优先用稳定机器名，展示名仅作兜底。
4. **经典 `<script>` 顶层函数泄漏全局导致白屏** → IIFE 包裹共享脚本 → 教训：多页面共用的浏览器脚本一律 IIFE + 显式命名空间。
5. **contextBridge 暴露对象在主世界只读**，冒烟测试无法猴补 → 改为数据层故障注入开关 → 教训：E2E 注入点要设计在主进程侧。
6. **打包下载链路全部依赖 GitHub，国内网络不可达** → npmmirror 镜像 + @electron/packager 用本地缓存 → 教训：Electron 项目初始化就要配好 `ELECTRON_MIRROR`。

## 若重来会怎么改
- PRD 非功能指标先做一次基线测量再写数值（Electron 空载内存实测 ~300MB，200MB 的目标从一开始就不成立）。
- 窗口拖拽/缩放/走动的集成测试应尽早进入冒烟脚本（DPI 漂移类问题靠肉眼截图不易发现，靠「两次取尺寸」断言才抓到）。
- Q 版形象若追求更高质感，可评估「参数化 SVG 打底 + AI 生成细节贴片」混合方案，但当前 SVG 方案的可编程换装（配色/号码/名字/动作）是数据联动的核心优势，保持。
