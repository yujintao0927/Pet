# 调研报告：BoardPet 篮球桌面宠物　日期 2026-10-10

## 结论
做一款 Windows 桌面篮球主题电子宠物「BoardPet」：Q 版球星形象常驻桌面（默认詹姆斯/76 人配色），可拖拽、调大小、会走动庆祝；点击查看 NBA 赛程与进行中比赛的实时比分和球员数据。给个人 NBA 球迷自用。MVP 为「宠物本体 + NBA 实时数据面板 + 关注提醒/庆祝 + 个性化形象」四件套。数据源已实测 ESPN 免费公开接口在本机网络可用，建议立项。

## 1. 背景与目标
- 问题：现有桌宠只有观赏性（Bongo Cat、Shimeji），现有 NBA 数据应用只有工具性（腾讯体育、NBA app），没有「陪伴感 + 数据」结合的产品。
- 目标：桌面常驻的篮球伙伴——平时是会动的 Q 版球星，比赛日自动提醒开赛、关键时刻庆祝，点开就能看比分和球员数据。
- 成功标准：①宠物常驻且资源占用可接受（空闲 CPU <1%、内存 <200MB）；②进行中比赛的比分/球员数据延迟 ≤60 秒；③关注的比赛开赛/下半场/关键时刻能触发提醒与庆祝。

## 2. 用户与场景
- 用户：本人自用（中文界面，Windows 10/11）。
- 场景 1：工作学习时，詹姆斯 Q 版小人在桌面底部运球走动，支持球队得分时庆祝。
- 场景 2：比赛日晚，系统通知「76 人 vs 对手 已开赛」，点击直达比赛详情窗看实时比分与球员数据。
- 场景 3：换偏好——一键把形象换成库里或任意球员（通用身体 + 自选球队配色/号码/名字）。

## 3. 现状 / 竞品分析
| 方案 | 做法 | 可借鉴 | 局限 |
|---|---|---|---|
| [Bongo Cat](https://blog.csdn.net)（开源） | Electron + Live2D，键鼠互动桌宠 | 透明置顶无边框窗口方案、窗口穿透、模型自定义 | 无数据能力 |
| Shimeji 系列 | 精灵图 + 行为脚本，桌面走动 | 桌面行走/攀爬行为脚本思路 | 无数据、二次元向 |
| 腾讯体育/NBA app | 赛程与实时数据 | 数据展示结构（比分/节次/box score） | 纯工具，无陪伴感 |

差异化机会：**桌宠 × 实时赛事**——宠物本体与数据联动（庆祝、提醒），目前未见同类开源产品。

## 4. MVP 范围建议
- 必须包含：宠物常驻/拖拽/滚轮调大小/待机动画/桌面走动；预置 10~20 位球星 Q 版形象 + 通用身体自定义（配色/号码/名字）；赛程面板（当日 + 切换日期）；比赛详情窗（实时比分/节次/双方球员 box score，可多开）；关注机制（我的球队 + 单场星标）；开赛/下半场提醒（系统通知 + 宠物动作）；关键时刻庆祝；设置面板（行为开关/大小/开机自启）。
- 明确不做：直播视频、录像回放、高阶数据、多语言、macOS/Linux、付费数据源、账号云同步、养成系统、用户上传图片形象。
- 待定：无。

## 5. 约束与风险
| 风险 | 等级 | 应对 |
|---|---|---|
| NBA 官方接口（cdn.nba.com）在本机网络被 Akamai 拒绝（已实测 Access Denied） | 高 | 改用 ESPN 免费公开接口，已实测可用（scoreboard/summary/teams 均通，含 boxscore 与 plays）；保留数据源抽象层便于替换 |
| 免费接口无 SLA，字段结构可能变化 | 中 | 数据解析层集中封装 + 容错展示「数据不可用」；解析逻辑用单元测试锁定 |
| Q 版素材一致性（AI 生成难保证多动作统一） | 中 | 采用**参数化 SVG 矢量小人**（可编程换配色/号码/名字/动作），不依赖位图素材 |
| Electron 体积与内存偏高 | 低 | 个人自用可接受；绿色版免安装分发 |

## 6. 待定项
- 无（技术选型 Electron、形象方案、行为丰富度均已在需求对齐阶段拍板，见 docs/需求对齐单.md）。
